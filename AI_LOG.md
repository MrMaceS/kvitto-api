## Ключевые запросы к ассистенту

### Запрос 1: Архитектура и модели данных

**Контекст, который я дал:**
> "Нужно сделать API для приёма платежей на FastAPI. Стек: Python 3.11+, FastAPI, PostgreSQL, SQLAlchemy async, Pydantic v2. Ключевые моменты: деньги в копейках (integer), промокод -10%, рассрочка с графиком платежей, state machine для статусов, идемпотентность по Idempotency-Key. Предложи структуру проекта и начни с моделей."

**Что получил:** Структуру с разделением на models/schemas/routers/services, модели SQLAlchemy с `Mapped[...]`.

**Что я проверил:** Убедился, что все суммы — `int`, нет `float`. Попросил убрать `default=` из моделей (это Python-дефолт, а не БД-дефолт — может ввести в заблуждение).

### Запрос 2: Алгоритм рассрочки

**Контекст:**
> "Нужно разделить сумму в копейках на N месяцев так, чтобы сумма графика была ровно равна amount. Пример из ТЗ: 1990000 / 3 = [663334, 663333, 663333]."

**Что получил:** Функцию `calculate_installment_schedule` с делением на `base_payment` и `remainder`.

**Что я проверил:** Вручную посчитал на калькуляторе:
- `1990000 // 3 = 663333`
- `1990000 % 3 = 1`
- `[663333+1] + [663333, 663333] = [663334, 663333, 663333]`
- `sum = 1990000` ✓

Попросил добавить `assert sum(schedule) == amount` — защита от будущих регрессий.

### Запрос 3: Тесты с asyncpg

**Контекст:**
> "Тесты падают с ошибкой `Event loop is closed` и `another operation is in progress` при использовании PostgreSQL."

**Что получил:** Вариант с глобальным `test_engine`.

**Что я заметил:** Ошибка не ушла. Сам докопался до причины — `pytest-asyncio` создаёт новый event loop для каждого теста, а глобальный движок "прилипает" к закрытому loop. Попросил переделать так, чтобы `engine` создавался и уничтожался (`dispose()`) внутри каждой фикстуры. После этого все тесты прошли.

## Где модель ошибалась или предлагала слабые решения

### 1. SQLite вместо PostgreSQL

**Ошибка:** ИИ предложил SQLite "для простоты".

**Как заметил:** По ТЗ можно PostgreSQL, и это более production-ready. Сразу попросил переделать.

### 2. `default=` в моделях

**Ошибка:** В моделях были `default=0` для `discount` и `default=PaymentStatus.PENDING` для `status`.

**Как заметил:** Я понял, что это Python-дефолт, а не БД-дефолт. Это может привести к путанице при прямых SQL-запросах. Попросил убрать и ставить значения явно в сервисе.

### 3. Тип для `schedule`

**Ошибка:** Изначально `schedule: Mapped[list | None]` без параметризации.

**Как заметил:** Для type hints лучше `list[int] | None`. Попросил исправить.

### 4. Валидация `installment_months`

**Ошибка:** Валидатор проверял `installment_months` только для метода `installment`, но не запрещал передавать это поле для `card`/`sbp`.

**Как заметил:** Подумал, что если клиент передаст `installment_months=3` для метода `card`, это должно быть ошибкой валидации. Попросил добавить проверку.

### 5. Утечка соединений в тестах

**Ошибка:** После первого теста следующие падали с `Event loop is closed`.

**Как заметил:** Сам разобрался в документации `pytest-asyncio` и нашёл, что нужно создавать engine внутри фикстуры, а не глобально.
